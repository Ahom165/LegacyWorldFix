Date: 14 novembre 2026

== Contexte : nouveau layout de stockage 26.x ==
Le jar 26.3 résolu le 14/11 au matin (même id « 26.3 », même data version
5023) lit les chunks dans dimensions/minecraft/<dimension>/region/ et déplace
les anciens dossiers via DimensionStorageFileFix pendant le pass d'upgrade
vanilla (« Cannot move file from /region to
dimensions/minecraft/overworld/region: Target already exists » - observé).
Un monde estampillé DataVersion saute ce pass : la 1.6.0 laissait donc le jeu
régénérer silencieusement les mondes convertis sur ces builds (A/B prouvé :
même symptôme avec le jar 1.6.0).
